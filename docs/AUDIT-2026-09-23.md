# Audit — everything that is not corpus text · 2026-09-23

Scope: the **80 tracked files that are not the corpus JSON**. The 66 `.json` texts were
explicitly out of scope.

```sh
git ls-files | wc -l            # 146 tracked
git ls-files '*.json' | wc -l   #  66 corpus  <- out of scope
git ls-files | grep -vc '\.json$'  # 80 audit surface
```

Split: `docs/` 24 · `scripts/` 13 · `tests/` 14 · `sanskrit_texts/` 9 · `migrations/` 6 ·
root docs 5 · config/CI 9.

**Every finding below carries the command that reproduces it.** That is not ceremony: this
repo filed **G67** the day before this audit, about three reports asserting "98.5% alignment"
and "0 missing verses" against editions that were not on disk. An audit nobody can re-run is
the same artefact wearing a different title. Where a claim could not be checked it says so.

**One of the three audit passes produced a reproduction that did not reproduce** — it patched
`importer.REPO`, which `corpus_files(root=REPO)` binds as a *default argument* at definition
time, so it silently walked the real 66-text corpus and reported output it had not produced.
The underlying defect was real and is fixed below. The lesson is the one G67 already names:
re-run the load-bearing claim yourself. `tests/test_corpus_file_failures.py` carries that
warning in its module docstring so the next person patches the function, not the constant.

## The through-line

**Fourteen of the twenty-one findings are one defect class: a claim in one file that another
file does not keep.** `rule:adversarial-review-reads-the-ledger` names exactly this. G31,
`schema.py`, `DATABASE.md`, `CLAUDE.md`'s index claim, the "+3" block, `serialize()`'s
docstring, `conftest`'s cited filename — each was true when written, none is machine-checked,
so none could report that it had stopped being true.

The two *behavioural* defects (the importer's silent drop, `clean-db`'s missing guard) share a
different shape: **a safety property asserted in prose beside code that does not enforce it.**

## Open, ranked

### HIGH

**2 · SC-001 has two live instances, and one shifts every citation.** Not fixed here — it is a
converter bug, not hygiene, and wants its own pass.

```sh
python3 -c "
import json,pathlib,re
COLO=re.compile(r'(ऽध्यायः|अध्यायः|उपनिषत्|ब्राह्मणम्|खण्डः)\s*॥?\s*\$')
for p in pathlib.Path('.').rglob('*.json'):
    if any(x.startswith('.') for x in p.parts) or p.parts[0] in ('docs','venv'): continue
    try: d=json.loads(p.read_text(encoding='utf-8'))
    except Exception: continue
    if not isinstance(d,dict) or 'chapters' not in d: continue
    for c in d['chapters']:
        sh=c.get('shlokas',[])
        if len(sh)==1 and COLO.search((sh[0].get('text') or '').strip()):
            print(d['text_id'],'ch',c.get('number'))"
```

| text | shape | damage |
|---|---|---|
| `kaushitaki_upanishad` | ch2 holds only `प्रथमोऽध्यायः` — chapter **one**'s colophon | **Mid-text.** Every citation from ch2 on is shifted a whole chapter |
| `kaivalya_upanishad` | ch3 holds only `द्वितीयः खण्डः` — khaṇḍa **two**'s colophon | Trailing. Citations intact; ch3 should not exist |

The tell in both: **the colophon's ordinal is lower than the chapter holding it.**

**This closes a question this repo has open.** `CANONICAL_COUNTS.md` §"The +3 discrepancies, and
a hypothesis that failed" records Kauśītaki as unexplainably over its cited figure, having tested
and rejected the śānti-pāṭha explanation. Merge the stray verse back: **50 verses in 4 chapters,
exactly the cited canonical figure.** Nobody connected them because SC-001 was filed against a
different text in a different repo.

Fix has two halves: the two damaged texts, and `scripts/sanskrit-convert/convert.py:1263`, which
splits on verse-number restarts and knows nothing about colophons — while `apastamba.py:139`
already segments *by* colophon correctly. The knowledge exists in one per-text converter and
never reached the generic one.

**15 · `schema.py` does not exist.** `sanskrit_texts/__init__.py:18` and `models.py:4` both
describe it as the Pydantic layer owning "what LEAVES the building", framed as the structural fix
for G50. `find -iname schema.py` returns nothing; the real G50 enforcement is `_normalize_shloka`
in **astroacharya's** repo. Either build it or delete the claim — a reader currently believes a
publication boundary exists here that does not.
